### Important corrections and boundaries

- AmbiSQL's latest arXiv v2 (2026-03-23) has six authors and a revised SIGMOD 2026 demonstration abstract. Earlier search snippets still show v1's three-author abstract and numerical claims; those claims were not reused.
- Sphinteract's own PDF citation format gives 2024, PVLDB 18(4), although some later references call it 2025.
- EHRSQL is a NeurIPS 2022 paper even though its arXiv record was first submitted in January 2023.
- LatentRefusal has a Findings of ACL 2026 proceedings page, so it should not remain labeled solely as a January 2026 preprint.
- QDA-SQL's current v3 record, revised July 2026, names CICAI 2026 and uses a different author order from older indexes. Its first public preprint dates to 2024.
- TrustSQL (the reliability benchmark) is distinct from TRUST-SQL (2026 tool-integrated reinforcement learning over unknown schemas) and unrelated products also named TrustSQL.
- AmbiDB is the synthetic schema-linking benchmark in LinkAlign, EMNLP 2025. It tests database/schema ambiguity and is marked adjacent to intent clarification. A candidate Hugging Face URL returned HTTP 401, so a usable dataset release is not asserted.
- PRACTIQ's author repository is archived and documents generation code. A repository link alone is not taken to mean that an evaluation-ready dataset is available.
- SQUAB's Anthology abstract retains an anonymous repository URL, whereas its published PDF links https://github.com/spapicchio/squab ; the named repository was inspected and used.
- CLAMBSQL has an author-linked Hugging Face page with files but no dataset card. Downloadability, licensing and experimental reproducibility are separate checks.
- CLARITY resource availability was independently checked through its public GitHub repository: generation code and Spider/BIRD-derived data are present, with separate software and data licenses.
- ABISS explicitly limits its unanswerable labels to a model-council validation procedure rather than a formal impossibility proof. Its simulator also does not model all forms of user error or intent change.
- Scores across answerability classification, top-k interpretation coverage, clarified SQL prediction, simulated dialogue and penalty-based selective prediction are different tasks and should not be placed in one ranking.

### Exclusions and unresolved leads

- General benchmarks such as Spider, BIRD and WikiSQL are background dependencies rather than evidence that ambiguity or unanswerability was explicitly evaluated.

### Scope decisions

Core entries explicitly handle ambiguity, clarification, answerability, alternative interpretations, or uncertainty routing. Adjacent entries are included only when they explain a concrete missing-context or dynamic-interaction issue: enterprise business knowledge (EntSQL), changing database state (MultiSQL and DySQL-Bench), realistic workflows (Spider 2.0), and underspecified tabular QA (ODUTQA-MDC). LiveSQLBench is an upstream benchmark project with released datasets, not a published paper entry. IntentSQL is a public system with self-reported experiments, not a peer-reviewed result.

CoSQL and SParC are older foundations included for context. CoSQL includes ambiguous/unanswerable dialogue acts and recorded clarifications; SParC principally tests context-dependent parsing. Neither should be described as a new autonomous user-simulation benchmark.

### Artifact and identity findings

- **TIDE-Bench:** [paper](https://arxiv.org/abs/2608.29543) states code is released, but [linked repository](https://github.com/Rcrossmeister/TIDE-Bench) exposed only README, LICENSE, and .gitattributes on inspection. Mark as a placeholder and do not claim available evaluation code or data. This is distinct from [TIDE-Bench for tool-integrated reasoning](https://arxiv.org/abs/2605.09544).
- **TACO:** [paper](https://arxiv.org/abs/2606.14201) describes 14,500 examples; the [current author dataset card](https://huggingface.co/datasets/Akanezora/TACO-Benchmark) reports 12,422 JSON examples and 46 SQLite databases. Do not silently equate those counts. The card declares MIT and currently has a dataset-viewer cast error; downloaded-artifact usability was not tested.
- **BIRD-Interact:** [code](https://github.com/bird-bench/BIRD-Interact) is MIT; [Full data](https://huggingface.co/datasets/birdsql/bird-interact-full) is CC BY-SA 4.0. Full, Lite, and Mini-Interact are separate variants. The repository contains ADK, conversational, agentic, evaluator, and simulator modules. Evaluation access separates public examples from ground-truth information.
- **LiveSQLBench:** [site](https://livesqlbench.ai/) labels its paper coming soon and 1.5/2.0 as forthcoming. Existing [Base-Full-v1](https://huggingface.co/datasets/birdsql/livesqlbench-base-full-v1) and [Large-v1](https://huggingface.co/datasets/birdsql/livesqlbench-large-v1) are published, but both cards' metadata says CC BY 4.0 while their body says CC BY-SA 4.0. Leave licensing unresolved rather than assigning one silently.
- **CLUES:** [MIT code and examples](https://github.com/Bayer-Group/clues-clinical-nlp) are present. A standalone clinical dataset download was not located; the clinical study should not be presented as clinical deployment validation.
- **IntentRL:** [training/evaluation code](https://github.com/saparina/intentRL) and [text-to-SQL model](https://huggingface.co/irisaparina/IntentRL-Ambig-Text2SQL-4B) are public. Upstream AMBROSIA access remains via its author download; do not mirror that dataset.
- **MultiSQL:** [dataset repository](https://github.com/grandchicken/MultiSQL) provides a database download but still says evaluation code will be released. No code-available badge should be inferred from a repository existing.
- **ACT/AmbigSQL:** [reference implementation](https://github.com/google-research/google-research/tree/master/learning_to_clarify) is present, with a PACIFIC example workflow. A standalone AmbigSQL release was not verified.
- **AmbiSQL:** [current manuscript](https://arxiv.org/abs/2508.15276) describes a SIGMOD 2026 demonstration and six authors, unlike old search snippets. [Apache-2.0 code](https://github.com/JustinzjDing/AmbiSQL) is present; the demo was not exercised.
- **TraceSQL:** [verification paper](https://arxiv.org/abs/2608.17795) is unrelated to the TraceSQL lineage product and older SQL tracing systems. No verified code link was located for this paper.
- **FALCON:** [ambiguity-aware synthesis framework](https://arxiv.org/abs/2610.03625) is distinct from [Falcon Chinese enterprise benchmark](https://arxiv.org/abs/2510.24762) and its [repository](https://github.com/eosphoros-ai/Falcon). The enterprise benchmark is a valid adjacent lead but omitted here to keep the initial catalogue focused; its principal emphasis is enterprise dialect and schema/semantic complexity, not interactive answerability.
- **EntSQL, PlanPool, FALCON synthesis:** Papers verified; dedicated public code/data not located in the inspected manuscript links or exact-name searches. Absence from this search is not proof that no release exists.
- **ODUTQA-MDC:** [repository](https://github.com/jensenw1/ODUTQA-MDC) contains data and source directories despite a stale README line referring to eventual code publication. Dataset and code execution were not tested; licensing was not verified.
